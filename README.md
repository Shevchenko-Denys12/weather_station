# NUCLEO-F411RE · Interactive 3D Simulator

Інтерактивна 3D-модель плати **STM32 NUCLEO-F411RE** у браузері з симулятором прошивки на HAL.
Плата змодельована за фото ревізії MB1360C (`nucleo_f411re.webp`): micro-USB, U7 STM32F411RET6, JP2/JP3, LD1–LD4.
Nucleo і HW-084 стоять на латунних стійках, повнорозмірна макетка лежить нижче, тому дроти опускаються на неї зверху.

Поруч стоїть макетна плата зі схемою **D7 (PA8) → R1 220 Ω → LED1 → GND**.
Можна обертати сцену, наводити курсор і клікати на компоненти, запускати демо-прошивку
та дивитися, як спалахує LED1 і що приходить у Serial Monitor.

**Стек:** React 19 · Vite · `@react-three/fiber` · `@react-three/drei` · Tailwind CSS v4 · Zustand

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # статична збірка в dist/ (готова для Vercel / GitHub Pages)
```

## Що вміє

| Дія | Результат |
| --- | --- |
| Hover на компонент | підсвітка + підпис (`LD2 · PA5 / D13`) |
| Click на компонент | картка з описом і характеристиками (знизу зліва) |
| Hover на **будь-який пін** (Arduino, morpho, вивід МК) | підказка + підсвітка всього нету: PA5 світиться на U5·21, CN10·11 і D13 одночасно |
| Click на пін | картка: роз'єм, вивід МК, альтернативні функції, що підключено на платі, рівень HIGH/LOW |
| Перемикачі «Підписи пінів» | показати/сховати шари підписів Arduino / Morpho / MCU |
| **Запустити симуляцію** | виконується `main.c`, поточний рядок підсвічується, LED1 спалахує на 300 мс кожні 3 с |
| Click на **B1** (синя кнопка) | спадний фронт на PC13 → EXTI → період 3 с ↔ 1 с |
| Click на **B2** / Reset | перезапуск прошивки (NRST) |

## Метеостанція: модулі та з'єднання

Сцена показує схему з [C/README.md](C/README.md), зібрану на повнорозмірній макетці перед Nucleo
(ракурси «Макетка» `7`, «Зверху» `8`, «З'єднання» `9`). Значення датчиків поки не емулюються, показано лише підключення.

| Модуль | Ряди макетки | Підключення |
| --- | --- | --- |
| **OLED JMD0.96D-1** (SSD1306, 0x3C) | f55–f58 | +3V3, GND; SCL / SDA доріжками на ряди 49 / 50 |
| **GY-BMP280-3.3** (0x76) | f40–f45 | +3V3, GND, CSB → +3V3, SDO → GND; її ряди 42 / 43 = шина SDA / SCL |
| **DHT11**, модуль `+ − OUT` | f34–f36 | OUT → D6 (PB10), підтяжка на модулі |
| **Кнопка 12×12** (SW1) | через канал, ряди 28 / 30 | виводи 1–2 → D2 (PA10), 3–4 → GND |
| **HW-084** (DS3231 0x68, AT24C32 0x57) | позаду макетки, дроти на J1 | SQW / SCL / SDA прямо вниз у ряди 48 / 49 / 50, VCC / GND на шини; SQW доріжкою на ряд 33 → D4 (PB5) |

Правила розводки:

- Модулі стоять штирями в колонці f і нависають над передньою половиною. Уся проводка в задній половині (g–j)
  і на задніх шинах +3V3 / GND, ближчих до Nucleo. Порядок (з боку Nucleo, зліва направо): OLED, BMP280, DHT11, кнопка.
- Кожен модуль бере живлення з шини просто за ним короткою П-подібною перемичкою.
- Одна шина I²C на рядах SDA / SCL самого BMP280 (42 / 43): туди приходять D14 / D15, а HW-084 і OLED
  під'єднані пласкими доріжками вздовж рядів (як у типовій Fritzing-схемі).
- Дроти з Nucleo розходяться віялом без перехресть: гніздо, що стоїть далі позаду, приходить правіше.
  Скрипт перевірки дає 0 перехресть у проєкції згори.
- Кольори: +3V3 червоний, GND чорний, SCL жовтий, SDA зелений, SQW фіолетовий, DHT11 OUT синій, кнопка білий.
  Кожен дріт клікабельний і має свою картку.
- Мережі модулів об'єднані з мережами Nucleo (`data/netlist.js`): наведення на SCL будь-якого модуля підсвічує
  PB8 на МК, CN5-10, CN10-3 і SCL інших модулів.
- LED1 і резистор 220 Ω лежать поруч у пінопласті, не підключені. Демо-прошивка досі перемикає PA8.

## Керування

**Камера** (панель справа знизу, кнопка «?» показує підказку):

| Дія | Миша / клавіші |
| --- | --- |
| Обертання | ЛКМ, `Q` / `E` |
| Переміщення | ПКМ або Shift+ЛКМ, `W A S D` / стрілки (Shift: швидше) |
| Зум до курсора | колесо, `+` / `−` |
| Фокус на деталі чи піні | подвійний клік, або `F` для останнього вибраного |
| Готові ракурси | кнопки або `1`…`9` (Огляд, Плата, МК, ST-LINK, CN7·CN6, CN5·CN10, Макетка, Зверху, З'єднання), `R`: скинути |

**Панель коду:** ширину змінює перетягування лівого краю, висоту Serial Monitor — перетягування смужки над ним.
Обидва роздільники працюють і зі стрілками на клавіатурі; подвійний клік скидає розмір.
Кнопка `›` ховає панель, «Код і Serial» повертає її. Розміри запам'ятовуються в браузері.

### Потік даних

```
 Run ─▶ runtime.runFirmware()
          │
          ▼
   firmware.main({ HAL, at })        at('HAL_Delay(') ─▶ store.activeLine ─▶ CodeViewer
          │
          ├─ HAL.GPIO_WritePin('PA8')  ─▶ store.gpio.PA8 ─▶ <ThtLed on> (LED1 на макетці) + індикатор D7
          ├─ HAL.UART_Transmit(msg)    ─▶ store.serial   ─▶ SerialMonitor
          └─ await HAL.Delay(ms)          (AbortSignal → Stop/Reset)

 Click B1 ─▶ store.gpio.PC13 = 0 ─▶ mock NVIC (subscribe) ─▶ HAL_GPIO_EXTI_Callback
```

**Чому код «двійник», а не інтерпретатор C?** Він простий, детермінований і дає точну
відповідність рядків: `at('<фрагмент>')` шукає рядок у тексті C, тож номери рядків
ніде не прописані вручну. Коли з'явиться справжня прошивка, замініть `SOURCE` у
[`firmware.js`](src/simulator/firmware.js) своїм `main.c` і оновіть `main()`.

### Як перепідключити LED1 на інший пін

1. У [`LedCircuit.jsx`](src/components/circuit/LedCircuit.jsx) змініть `SIGNAL_PIN` (наприклад, `'D4'`). Жовта перемичка сама перейде у потрібне гніздо, бо позиції беруться з `socketPos()`.
2. У [`firmware.js`](src/simulator/firmware.js) оновіть `#define LED_EXT_Pin` / `LED_EXT_GPIO_Port` у C-коді та `LED_EXT_Pin` у JS-двійнику (таблиця пінів — `ARDUINO_TO_MCU` у `data/layout.js`).
3. Додайте новий пін до `INITIAL_GPIO` у store.

### Як додати новий компонент (наприклад, датчик BME280)

1. Додайте опис у `data/components.js` під новим `id`.
2. Змоделюйте його в `board/parts.jsx` і загорніть у `<Interactive id="bme280">` у `NucleoBoard.jsx`.
3. Додайте в `hal.js` потрібну периферію (`I2C_Mem_Read`…), а стан датчика — у store.

## Розпіновка

Усі 172 піни (64 виводи МК, 2 × 38 morpho і 32 Arduino) описані в [`pinout.js`](src/data/pinout.js) за UM1724 / DS10314.
Кожен запис має позицію у 3D, нет, тип і альтернативні функції, тож модель, підказки й дроти на макетці
беруть дані з одного місця. Arduino-роз'єми вирівняні по сітці morpho, CN5 зміщений на півкроку
(класичний зазор 160 mil між D7 і D8 у Uno).

## Відповідність пінів

| Плата | Пін МК | Arduino |
| --- | --- | --- |
| LED1 (макетка, через 220 Ω) | PA8 | D7 |
| LD2 (зелений LED) | PA5 | D13 |
| B1 (User) | PC13 | — |
| USART2 TX/RX (ST-LINK VCP) | PA2 / PA3 | D1 / D0 |
