# Метеостанція на NUCLEO-F411RE: схема підключення

Прошивка для STM32F411RET6 (плата NUCLEO-F411RE). Температуру вимірюють два датчики, BMP280 і DHT11, і їхні
показники перевіряють та уточнюють один одного (див. [«Фільтр двох датчиків температури»](#фільтр-двох-датчиків-температури)).
BMP280 додатково дає тиск, DHT11 дає вологість. Кожні 15 хвилин станція записує дані в EEPROM модуля HW-084
і показує їх на OLED. Кнопка перемикає чотири екрани:

1. Поточні дані: час, температура, вологість, тиск.
2. Історія: мінімум і максимум за збережений період.
3. Графік температури.
4. Графік тиску.

---

## Що варто знати перед збиранням

1. **Усе живимо від 3.3 V.** BMP280 працює тільки від 3.3 V. HW-084 має на SDA/SCL підтяжки 4.7 kΩ до власного VCC:
   якщо живити його від 5 V, на шині I²C буде 5 V, і BMP280 це пошкодить. DHT11 теж живимо від 3.3 V, тоді на
   лінії DATA буде безпечний для МК рівень. Шина 5 V у цій схемі не використовується.
2. **Дріт до DHT11 не довший за 20 см.** За datasheet при живленні нижче 3.5 V довший кабель дає збої зв'язку.
3. **DHT11 опитуємо не частіше ніж раз на 2 с** (datasheet вимагає щонайменше 1 с). Після ввімкнення живлення
   датчику треба близько 1 с на запуск.
4. **BMP280 і DHT11 ставимо поруч**, щоб обидва вимірювали те саме повітря, інакше взаємна фільтрація втрачає
   сенс. Обидва датчики ставимо подалі від OLED, плати Nucleo і HW-084, бо ті гріються.
5. **Ланцюг заряду батареї на HW-084.** На більшості модулів цього типу (клон ZS-042) стоїть резистор 200 Ω і
   діод, які заряджають батарею від VCC. Вони розраховані на акумулятор LIR2032. Зі звичайною CR2032 при 3.3 V
   струм заряду майже нульовий, але якщо модуль колись опиниться на 5 V, батарею почне заряджати. Для CR2032
   краще випаяти цей діод або резистор (перевір на своїй платі, біля тримача батареї).
6. **Зовнішні підтяжки I²C не потрібні.** Вони вже є на модулях: паралельно виходить приблизно 2.5–3 kΩ,
   а це нормально для 3.3 V (струм ≈ 1.3 мА при допустимих 3 мА).

## Загальна схема

Вертикальні лінії позначають шини, `●` означає з'єднання з шиною, `┼` означає перетин без з'єднання.

```
                                  +3V3    GND    SCL    SDA
                                    │      │      │      │
 NUCLEO-F411RE                      │      │      │      │
   CN6-4   3V3 ─────────────────────●      │      │      │
   CN6-6   GND ─────────────────────┼──────●      │      │
   CN5-10  D15 · PB8 · I2C1_SCL ────┼──────┼──────●      │
   CN5-9   D14 · PB9 · I2C1_SDA ────┼──────┼──────┼──────●
                                    │      │      │      │
 OLED JMD0.96D-1 (SSD1306) 0x3C     │      │      │      │
   GND ─────────────────────────────┼──────●      │      │
   VCC ─────────────────────────────●      │      │      │
   SCL ─────────────────────────────┼──────┼──────●      │
   SDA ─────────────────────────────┼──────┼──────┼──────●
                                    │      │      │      │
 HW-084, роз'єм J1                  │      │      │      │
   DS3231 0x68 · AT24C32 0x57       │      │      │      │
   32K  (не підключати)             │      │      │      │
   SQW  ─▶ D4 · PB5  (схема В)      │      │      │      │
   SCL ─────────────────────────────┼──────┼──────●      │
   SDA ─────────────────────────────┼──────┼──────┼──────●
   VCC ─────────────────────────────●      │      │      │   ← саме 3.3 V, не 5 V!
   GND ─────────────────────────────┼──────●      │      │
                                    │      │      │      │
 GY-BMP280-3.3 0x76                 │      │      │      │
   VCC ─────────────────────────────●      │      │      │
   GND ─────────────────────────────┼──────●      │      │
   SCL ─────────────────────────────┼──────┼──────●      │
   SDA ─────────────────────────────┼──────┼──────┼──────●
   CSB  (вибір I²C) ────────────────●      │      │      │
   SDO  (адреса 0x76) ──────────────┼──────●      │      │
                                    │      │      │      │
 DHT11 (модуль + − OUT)             │      │      │      │
   +   ─────────────────────────────●      │      │      │
   OUT ─▶ D6 · PB10  (схема А)      │      │      │      │
   −   ─────────────────────────────┼──────●      │      │
                                    │      │      │      │
 SW1, кнопка 12×12                  │      │      │      │
   1  ─▶ D2 · PA10  (схема Б)       │      │      │      │
   4 ───────────────────────────────┼──────●      │      │
```

> Порядок виводів на OLED буває різним (`GND VCC SCL SDA` або `VCC GND SCL SDA`). Перед підключенням
> звір його з написами на своїй платі. Те саме стосується модулів DHT11 з трьома виводами.

### Схема А: DHT11 (модуль) → D6 (PB10)

```
              ┌──────────────────────────────┐
              │  DHT11, модуль               │
   +3V3 ──────┤ +    ┌─────┐                 │
              │      │ 10k │ R1 (на платі)   │
   D6 · PB10 ◀┤ OUT ─┴─────┘                 │
   CN9-7      │        ═╪═ C1 100 nF         │
   GND ───────┤ −       │    (на платі)      │
              └──────────────────────────────┘
```

**Виводи модуля** (як надруковано на платі): **`+` = VCC, `−` = GND, `OUT` = дані.**
Підтяжка OUT до VCC модуля і конденсатор 100 nF уже стоять на платі, тож досить трьох дротів, зовнішні R1 і C1
не потрібні. Модуль живимо від 3.3 V, тоді й підтяжка тягне OUT до 3.3 V, безпечних для МК.

Якщо колись знадобиться «голий» DHT11 з 4 ніжками: решіткою до себе, ніжками вниз, зліва направо
1 = VCC, 2 = DATA, 3 = NC, 4 = GND, а R1 4.7–10 kΩ (DATA → 3.3 V) і C1 100 nF (VCC → GND) ставимо поруч на макетці.

**Як МК читає DHT11.** PB10 налаштовується як вихід з відкритим стоком: МК тягне лінію в LOW, а коли відпускає,
підтяжка на модулі піднімає її до HIGH. Рівень можна читати з `IDR` у тому самому режимі. Обмін виглядає так:

1. МК тримає лінію в LOW ≥ 18 мс, потім відпускає.
2. Датчик відповідає: 80 мкс LOW, 80 мкс HIGH.
3. Далі йдуть 40 біт. Кожен біт починається з 50 мкс LOW, після чого HIGH триває 26–28 мкс (це `0`)
   або 70 мкс (це `1`).
4. Байти: вологість (ціла, дробова), температура (ціла, дробова), контрольна сума = молодші 8 біт суми перших чотирьох.

Весь обмін триває ≈ 4 мс. Для відліку мікросекунд підійде `DWT->CYCCNT` (при 100 MHz крок 10 нс) або
TIM2 з тактом 1 MHz. На ці 4 мс переривання краще вимкнути: натискання кнопки не загубиться,
бо EXTI запам'ятає його в pending-біті.

### Схема Б: кнопка SW1 → D2 (PA10)

```
          3.3 V
            │
           ┌┴┐  ≈ 40 kΩ, внутрішня підтяжка PA10 (зовнішній резистор не потрібен)
           └┬┘
            ├────────────┬────────────▶ D2 · PA10 · CN9-3
            │            │
            o 1          │
             \  SW1     ═╪═ C2 100 nF (необов'язково)
            o 4          │
            │            │
           GND          GND
```

У кнопки 12×12 виводи 1–2 з'єднані завжди, 3–4 теж. Натискання замикає пару 1–2 з парою 3–4, тому беремо
виводи по діагоналі (1 і 4): так помилитися з парою неможливо.

PA10 налаштовується як `GPIO_EXTI10`, Pull-up, переривання за спадним фронтом. Натиснута кнопка дає LOW.
Брязкіт контактів усуваємо програмно (ігнорувати повторні фронти протягом 30–50 мс). C2 зменшує брязкіт апаратно.

Синя кнопка B1 на самій Nucleo (PC13) лишається вільною, її можна використати для чогось іншого, наприклад
довге натискання = встановлення часу.

### Схема В: будильник DS3231 → D4 (PB5), рекомендовано

```
  HW-084 SQW (open-drain, активний LOW) ──────▶ D4 · PB5 · CN9-5
                                                (GPIO_EXTI5, Pull-up, спадний фронт)
```

DS3231 сам будить МК рівно о :00, :15, :30, :45. Будильник Alarm 1 налаштовується на збіг хвилин і секунд,
`INTCN = 1`, `A1IE = 1`. Після кожного спрацювання прошивка скидає прапорець `A1F` і ставить наступну чверть години.
Без цього дроту станція теж працюватиме, якщо прошивка сама опитуватиме час з RTC.

Для мікросекундних інтервалів DHT11: увімкнути `DWT->CYCCNT` (через `CoreDebug->DEMCR`) або TIM2 з prescaler
на 1 MHz. PB10 також має вихід `TIM2_CH3`, тож пізніше читання можна перевести на input capture без переробки схеми.

при 5 V. Якщо на твоєму модулі стоїть AT24C32D або новіший, можна поставити 400 kHz: повне оновлення
OLED (1 КБ) займе ≈ 25 мс замість ≈ 95 мс. Для метеостанції з оновленням раз на секунду вистачить і 100 kHz.

D7 (PA8) не зайнятий: на нього в симуляторі вже підключено світлодіод LED1 на макетці, його можна лишити як
індикатор.

## Фільтр двох датчиків температури

Датчики суттєво відрізняються, тому фільтр не просто усереднює їх, а враховує, наскільки кожному можна вірити:

| | BMP280 | DHT11 |
| --- | --- | --- |
| Точність температури | ±1 °C | ±2 °C |
| Роздільна здатність | 0.01 °C | 1 °C (нові ревізії 0.1 °C) |
| Діапазон | −40…85 °C | 0…50 °C |
| Як часто можна опитувати | хоч щоразу | не частіше ніж раз на 1–2 с |
| Що ще вимірює | тиск | вологість 20…90 % (±5 %) |

Цикл вимірювання повторюється **кожні 2 с**:

1. **Перевірка кожного датчика окремо.**
   - BMP280: пристрій відповів по I²C (ACK), сирий код температури не `0x80000` (вимірювання пропущене),
     результат у межах −40…85 °C.
   - DHT11: датчик відповів на старт, контрольна сума збіглася, температура 0…50 °C, вологість 0…100 %.
   - Перевірка на стрибок: значення відрізняється від попереднього відфільтрованого більш ніж на 2 °C за 2 с.
     У кімнаті чи на вулиці повітря так швидко не змінюється, тож це викид, і значення відкидаємо.
2. **Корекція зсуву DHT11 за BMP280.** Якщо обидва датчики пройшли перевірку і різниця між ними менша за 3 °C
   (сума їхніх допусків), прошивка повільно оцінює систематичний зсув DHT11 відносно точнішого BMP280
   (ковзне середнє, α = 0.01, це кілька хвилин) і додає його до показань DHT11. Тоді DHT11 стає точним
   запасним датчиком, якщо BMP280 відмовить.
3. **Об'єднання.**
   - Обидва валідні й узгоджені (різниця ≤ 2 °C після корекції): зважене середнє з вагами, оберненими до
     квадрата похибки (σ ≈ половина допуску: 0.5 і 1.0 °C), тобто **T = 0.8 · T_BMP + 0.2 · T_DHT**.
   - Обидва валідні, але розходяться: беремо той, що ближчий до попереднього відфільтрованого значення.
     Якщо розбіжність тримається понад 5 циклів поспіль (10 с), ставимо прапорець `MISMATCH` і показуємо `!`
     на екрані 1.
   - Валідний лише один: беремо його і ставимо прапорець, який саме датчик відмовив.
   - Обидва невалідні: лишаємо попереднє значення і ставимо прапорець `NO_DATA`.
4. **Згладжування.** Для екрана беремо ковзне середнє (α = 0.3). У EEPROM пишемо середнє всіх валідних
   об'єднаних значень за 15 хвилин (≈ 450 відліків), що прибирає і шум, і крок 1 °C у DHT11.

```c
/* Sketch of one 2 s cycle; tolerances in °C */
bool b_ok = bmp_ok && in_range(t_bmp, -40, 85) && fabsf(t_bmp - t_prev) < 2.0f;
bool d_ok = dht_ok && in_range(t_dht,   0, 50) && fabsf(t_dht + bias - t_prev) < 2.0f;

if (b_ok && d_ok && fabsf(t_bmp - t_dht) < 3.0f)
    bias += 0.01f * ((t_bmp - t_dht) - bias);        /* slow DHT11 offset tracking */

float t_d = t_dht + bias;
if (b_ok && d_ok && fabsf(t_bmp - t_d) <= 2.0f) t = 0.8f * t_bmp + 0.2f * t_d, mismatch = 0;
else if (b_ok && d_ok) t = closer_to(t_prev, t_bmp, t_d), mismatch++;
else if (b_ok)         t = t_bmp;
else if (d_ok)         t = t_d;
else                   t = t_prev;                    /* NO_DATA */
```

Вологість дає тільки DHT11, тиск тільки BMP280. Для них діє лише перевірка діапазону, стрибків і контрольної суми.

## Живлення

Усе живиться від USB через ST-LINK, окреме джерело не потрібне.

| Споживач | Шина | Струм (типово) |
| --- | --- | --- |
| OLED SSD1306 | 3.3 V | 10–20 мА (залежить від кількості світних пікселів) |
| HW-084 (DS3231 + світлодіод живлення) | 3.3 V | ≈ 0.2 мА + ≈ 1–3 мА LED |
| AT24C32 | 3.3 V | 3 мА під час запису, мкА в очікуванні |
| BMP280 (forced mode) | 3.3 V | < 1 мА у пікові моменти |
| DHT11 | 3.3 V | ≈ 1 мА під час вимірювання, ≈ 0.1 мА в очікуванні |
| **Разом на 3.3 V** | | **< 30 мА**, великий запас для регулятора Nucleo |

## Збирання на макетці

Повнорозмірна макетка (830 точок, 63 ряди) лежить перед Nucleo, ряди йдуть зліва направо. Правило одне:
**модулі стоять штирями в колонці f і нависають над передньою половиною (a–e), уся проводка йде в задній
половині (g–j) та на задніх шинах, ближчих до Nucleo.** Передні шини не використовуються.

| Ряди | Що | Підключення |
| --- | --- | --- |
| 4–9 | BMP280 (SDO, CSB, SDA, SCL, GND, VCC) | перемички з j на задні шини; SCL/SDA доріжками h/i до шини |
| 12–14 | DHT11 (OUT, −, +) | `+`/`−` перемичками на шини, OUT дротом на D6 |
| 26 / 28 | SW1 через канал (виводи 1–2 / 3–4) | ряд 26 ← D2, ряд 28 → GND |
| 31 | вузол SQW | HW-084 SQW і D4 |
| 33 / 34 | шина SCL / SDA | D15 / D14, HW-084, доріжки від BMP280 (зліва) та OLED (справа) |
| 50–53 | OLED (GND, VCC, SCL, SDA) | перемички на шини; SCL/SDA доріжками g/h до шини |

- Задні шини: червона **+3V3** (від CN6-4), синя **GND** (від CN5-7). Кожен модуль бере живлення короткою
  П-подібною перемичкою з колонки j на шину просто за ним, ніколи з протилежного боку.
- BMP280 і DHT11 стоять поруч на лівому краю, подалі від OLED (правий край) і HW-084, які гріються.
- HW-084 лежить праворуч від Nucleo, кутовим роз'ємом до макетки, дроти «мама–тато» йдуть прямо вперед.
- Дроти I²C коротші за 20–30 см, дріт OUT до DHT11 коротший за 20 см.
- Перший запуск: просканувати шину (адреси 1…127) і перевірити, що відповідають рівно чотири пристрої:
  `0x3C`, `0x57`, `0x68`, `0x76`. Якщо `0x76` немає, а є `0x77`, значить SDO на BMP280 не притягнутий до GND.
  Потім прочитати DHT11 кілька разів і переконатися, що контрольна сума сходиться.

## Скільки історії влізе в AT24C32

AT24C32 має 4096 байт, сторінки по 32 байти, час запису ≈ 10 мс, ресурс 1 000 000 циклів на комірку.
Запис 16 байт ділить сторінку рівно навпіл, тож жоден запис не перетинає межу сторінки:

| Поле | Тип | Байти |
| --- | --- | --- |
| час (Unix) | `uint32` | 4 |
| T після фільтра, ×100 °C | `int16` | 2 |
| T BMP280, ×100 °C | `int16` | 2 |
| T DHT11, ×2 °C (крок 0.5 °C) | `int8` | 1 |
| тиск, ×10 гПа (300.0…1100.0 → 3000…11000) | `uint16` | 2 |
| вологість, % | `uint8` | 1 |
| прапорці (`BMP_FAIL`, `DHT_FAIL`, `MISMATCH`) | `uint8` | 1 |
| порядковий номер | `uint16` | 2 |
| CRC-8 | `uint8` | 1 |

- Відсутнє значення записуємо як `0x8000` / `0x80` / `0xFF`, щоб графік показав розрив, а не нуль.
- 4096 / 16 = **256 записів × 15 хв = 64 години** (≈ 2 доби 16 год) у кільцевому буфері.
- Графік шириною 128 пікселів = 128 останніх записів = **32 години**.
- Позицію голови буфера не треба зберігати окремо: після старту прошивка знаходить запис з найбільшим
  порядковим номером. Так жодна комірка не перезаписується частіше ніж раз на 64 години, і ресурсу EEPROM
  вистачить з величезним запасом.
